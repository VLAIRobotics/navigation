# 数据录制与问题排查

相关操作步骤收在同一篇中，按下面的任务标题查找。

<a id="recording"></a>

## 录制与离线分析

录包是把 ROS 话题保存到硬盘，方便之后查看当时收到了什么数据。先确定要解决什么问题，再开始录；点云和地图数据可能占用很多空间。

### 1. 录制 Nav2 运行过程

#### 1. 先启动导航

在第一个终端按所需路线启动 Nav2，并让它保持运行。只做录制和排查时，底盘必须是关闭状态：

~~~bash
cd /home/nvidia/nav2.0
./tool/start_nav2.sh config_file:=mid360.yaml sensor_height:=0.25 visualize:=false enable_chassis:=false
~~~

也可以记录地图导航，但不要同时启动两条导航流程。

#### 2. 开第二个终端启动录制

按 `Ctrl+Alt+T` 再开一个终端，进入项目目录并加载环境：

~~~bash
cd /home/nvidia/nav2.0
source /opt/ros/humble/setup.bash
source install/setup.bash
mkdir -p PCD
df -h .
~~~

`df -h .` 会显示项目所在磁盘的剩余空间。确认空间够用后，启动录制：

~~~bash
./tool/record_nav2_stability.sh PCD/nav2_first_run
~~~

`PCD/nav2_first_run` 是这次记录的文件夹名称。下次录制请换一个新名字；不要直接重复使用已有目录。

脚本会在这个目录下创建 `bag/` 保存话题，在旁边写入 `resources.jsonl` 保存 CPU、内存等资源采样。启动日志会显示保存位置和录制话题。它不会控制底盘。

#### 3. 结束录制并检查文件

录够需要的过程后，点回运行录制脚本的第二个终端，按 `Ctrl+C`，等待 rosbag 完成收尾。不要在第一个导航终端按 Ctrl+C，除非你也想停止导航。

检查录制包：

~~~bash
ros2 bag info PCD/nav2_first_run/bag
ls -lh PCD/nav2_first_run
~~~

第一条会列出录包时间、话题名称和消息数量；第二条检查输出目录是否有文件。若录制时看不到话题，先检查导航本身有没有发布这些话题。

加 `--raw` 会额外录制 MID360 原始雷达和 IMU 数据，文件增长更快、占用更多磁盘。只有排查雷达原始数据时才加：

~~~bash
./tool/record_nav2_stability.sh PCD/nav2_raw_check --raw
~~~

### 2. 录制 FastDEM 四阶段数据

这个脚本只负责保存数据，不会替你开车。运行前，FastDEM 和传感器链必须已经启动；每个阶段需要由现场操作员按提示手动完成。只有场地安全、有人守着急停、且你知道如何让机器人低速移动时才做。若你还不熟悉机器人操作，先跳过这项采集。

~~~bash
cd /home/nvidia/nav2.0
source /opt/ros/humble/setup.bash
source install/setup.bash
./tool/record_fastdem_terrain_baseline.sh /tmp/fastdem_baseline_01
~~~

每阶段约 30 秒，按终端提示操作。提前按 `Ctrl+C` 会留下不完整数据，不能当作完整四阶段记录。

四段依次是：平地静止 30 秒、低速直行 30 秒、低速转弯 30 秒、越过一个真实的小门槛或凸起 30 秒。终端出现 `Starting stationary`、`Starting straight`、`Starting turn`、`Starting threshold` 时，表示对应阶段开始。按现场安全要求动作，不能安全完成的阶段不要硬做。

这条命令会直接在 `/tmp/fastdem_baseline_01/` 建立 rosbag 目录，并在旁边生成 `fastdem_baseline_01.record.log`。录完出现 `Baseline recording complete` 后再分析；若中途退出，这次目录不能当作完整基线。

### 3. 分析已有数据

这些命令读取已经录好的 rosbag，不会驱动底盘。运行前进入仓库根目录；若路径不同，请把下面示例路径换成实际文件。

分析 FastDEM 四阶段数据。输入路径是上面录制命令生成的目录本身，不需要在末尾再加 `/bag`：

~~~bash
cd /home/nvidia/nav2.0
source /opt/ros/humble/setup.bash
source install/setup.bash
python3 tool/analyze_fastdem_terrain_baseline.py /tmp/fastdem_baseline_01
~~~

分析底盘速度响应（需要专门录制的正、反向速度脉冲数据；普通导航包不够）：

~~~bash
python3 tool/analyze_chassis_response.py /path/to/chassis_test_bag
~~~

统计地图可通行、占据和未知区域（地图转换后会有 PGM 文件）：

~~~bash
python3 tool/analyze_pcd_terrain_map.py --map PCD/clean_map_nav/map.pgm
~~~

如果示例文件不存在，先用 `ls` 找到真实的 bag 或 PGM 路径，再替换命令中的路径。`/path/to/...` 只是占位写法，不要原样输入。

### 4. 需要对照日志时

启动脚本的终端日志在 `logs/`，录制数据放在对应的 PCD 或 `/tmp/` 文件夹。把日志、rosbag、地图文件名和使用的 YAML 配置一起保留，之后才容易复现问题。

<a id="troubleshooting"></a>

## 常见问题与日志查看

这部分保留录制和日志方面的细节。第一次排查启动、雷达、地图或导航问题，建议先打开[常见问题检查与解决](常见问题检查与解决.md)，按每一步确认后再继续。

遇到错误时，先不要连续重跑。看启动终端里最早出现的报错，通常比最后一行更有用。

### 1. 先确认终端和环境

在报错的终端里运行：

~~~bash
pwd
ls
~~~

`pwd` 应显示仓库根目录，`ls` 应能看到 `src` 和 `tool`。如果当前目录不对，先执行 `cd /home/nvidia/nav2.0`；如果你的仓库在别处，把路径改成实际位置。

手动运行 `ros2` 命令前，在当前终端重新加载环境：

~~~bash
source /opt/ros/humble/setup.bash
source install/setup.bash
~~~

每个新终端都要各自加载一次。

### 2. 找启动日志

本项目脚本会把终端输出同时写到 `logs/`。查看最新日志文件名：

~~~bash
cd /home/nvidia/nav2.0
ls -lt logs | head
~~~

`total ...` 是目录统计，不是日志文件；它下面第一条文件名通常是最近生成的日志。把下面示例中的文件名换成列表里的真实文件名，再查看末尾 80 行：

~~~bash
tail -n 80 logs/start_board_20261105_120000.log
~~~

把报错前后约 20 行一起保存，便于判断问题发生在哪个程序。

### 3. 常见报错

#### 3.1 `ros2: command not found`

当前终端没有加载 ROS，或 ROS 没装好。先执行 [终端操作入门](环境准备与终端操作.md)里的环境加载命令。如果 `/opt/ros/humble/setup.bash` 不存在，回到[环境搭建](环境准备与终端操作.md)修复安装。

#### 3.2 找不到 `bringup`、FAST-LIO 或 Livox 程序包

先确认构建成功，然后在当前终端运行：

~~~bash
cd /home/nvidia/nav2.0
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 pkg list | grep bringup
~~~

如果没有输出，通常是还没编译、编译失败，或加载了错误工作区。重新打开[原生安装与编译](环境准备与终端操作.md)的编译步骤检查。

#### 3.3 `/livox/lidar` 没有数据

在新终端加载环境后运行：

~~~bash
ros2 node list
ros2 topic list
~~~

如果没有 Livox 节点，先看启动日志里的第一个错误。如果有节点但没有 `/livox/lidar`，检查雷达供电、网线、网卡地址和路由：

~~~bash
ip -br addr
nmcli device status
ip route get 192.168.1.194
~~~

把最后一行的示例地址换成雷达实际 IP；输出中的 `dev` 应为雷达网口，`src` 应为电脑网口地址。然后核对 Livox JSON 中的 `host_ip`、`lidar_ip` 和 `lidar_configs[].ip`。详细设置顺序见[MID360 接线与网络配置](设备接入与启动配置.md#mid360-network)。不要先改 Nav2 参数。

#### 3.4 RViz 打开了但画面空白

- 检查运行命令是否有 `visualize:=true`。
- 看启动终端是否有点云话题或坐标变换错误。
- 回到另一个终端运行 `ros2 topic list`，确认预期话题存在。
- 如果是远程连接或无图形桌面的终端，先用 `visualize:=false`，避免把显示问题误认为雷达没有数据。

#### 3.5 保存地图时提示找不到服务

保存服务只在建图流程运行期间存在。确认第一个终端还在运行 `start_fastlio_mapping.sh`，并且第二个终端已经加载了 ROS 和工作区环境。不要先按 Ctrl+C 停掉建图再保存。

#### 3.6 PCD 文件不存在或导航说无法读取

确认路径拼写、大小写和当前工作目录：

~~~bash
pwd
ls -lh PCD/clean_map.pcd
~~~

如果地图在其他位置，把 `pcd_file:=...` 改成对应的完整路径。文件大小为 0 时不能用于导航。

#### 3.7 地图定位没有通过

不要发送导航目标，也不要开启底盘。先确认使用的 PCD 是当前场地的地图，雷达能输出点云，`config_file` 和外参与设备一致。查看启动日志中的 GICP 定位错误；不确定时停止流程并找熟悉地图与传感器配置的人一起检查。

#### 3.8 报 CAN 接口错误

只查看软件时，在导航命令中使用 `enable_chassis:=false`。真车需要先由硬件负责人配置 CAN 接口、确认速率和急停。不要通过删除检查步骤来绕过错误。

#### 3.9 磁盘空间不足

查看剩余空间：

~~~bash
df -h
~~~

PCD 地图和 rosbag 可能很大。先确认文件用途，再删除不需要的数据；不要删除 `src/`、`install/` 或还要使用的地图。
