# Nav2 导航与 RViz 操作

相关操作步骤收在同一篇中，按下面的任务标题查找。

<a id="no-map-navigation"></a>

## 无图实时导航

这条流程使用 MID360 实时感知启动无静态 PCD 的导航，不需要先建好 PCD。导航使用 `odom` 坐标系，当前工作区还会维护在线地图并由目标管理链处理路线。第一次只查看定位和规划，不让底盘动；命令里的 <code>enable_chassis:=false</code> 要保留。RViz 面板和图层说明见[RViz 界面与导航操作](Nav2导航与RViz操作.md#rviz-guide)。

### 1. 启动前先确认

1. 已按[传感器处理流程](传感器建图与校准.md#sensor-check)确认 `/livox/lidar` 和 `/Odometry` 有数据。
2. 机器人附近有安全的空地。第一次不要在有人或障碍物旁边尝试驱动底盘。
3. CAN 设备、急停和速度标定还没确认时，不要启用底盘。
4. 没有其他终端正在运行传感器、建图或导航脚本。

### 2. 第一个终端：启动导航

按 `Ctrl+Alt+T` 打开终端，进入仓库根目录。路径不同的话，把示例路径改成你自己的路径：

~~~bash
cd /home/nvidia/l1_navigation
~~~

复制下面整条命令运行：

~~~bash
./tool/start_nav2.sh config_file:=mid360.yaml sensor_height:=0.25 visualize:=true enable_chassis:=false
~~~

脚本会启动雷达、FAST-LIO、地面处理、高程处理和 Nav2。它会自动加载 ROS 环境。`sensor_height:=0.25` 是示例安装高度，使用前要按实测值修改；不能确定时先咨询负责设备安装的人。

#### 选择底盘模型

默认使用双轮配置。全向轮配置就给启动脚本加一个参数，不需要填写配置文件路径：

~~~bash
./tool/start_nav2.sh chassis_model:=omni config_file:=mid360.yaml sensor_height:=0.25 visualize:=true enable_chassis:=false
~~~

脚本会从仓库内自动读取 `src/bringup/config/nav2_theta_teb_omni.yaml`。使用双轮时可省略 `chassis_model`，或写 `chassis_model:=two_wheel`。全向配置文件未放到指定位置时，脚本会提示缺少文件并停止启动。

全向参数文件和驱动也要适配实际底盘。当前 CAN 驱动尚未发送横移速度；只选全向 Nav2 参数不会让实车横移。首次切换仍保持 `enable_chassis:=false`，确认全向驱动和速度参数后再进行实车测试。

命令运行后不要关闭终端。RViz 应该打开，终端会继续显示节点运行信息。因为底盘关闭，机器人不会因这条命令移动；这个模式适合先检查界面和规划流程。

### 3. 在 RViz 里试发一个目标

只有当你看到机器人点云和位置正常时，再做这一步：

1. 在 RViz 顶部工具栏选择 `Nav2 Goal`（导航目标）工具；工作区默认 RViz 使用 Nav2 GoalTool，更多说明见[RViz 界面与导航操作](Nav2导航与RViz操作.md#rviz-guide)。
2. 在机器人附近的可见区域单击地图，并按住鼠标拖动一个方向箭头。
3. 松开鼠标后观察 RViz 中是否出现规划路径，以及终端是否继续显示运行信息。

先从机器人附近、点云和在线地图都显示正常的可通行位置开始测试。无图模式不加载既有 PCD；目标管理可能将较远目标分段执行，并等待新观测或报告受阻。观察导航诊断面板中的目标管理、规划和执行状态。不要把目标点选在未经观察的危险区域，也不要仅凭 RViz 画面判断实车周围安全。

### 4. 第二个终端：查看话题（可选）

如果想确认导航程序是否在发布数据，按 `Ctrl+Alt+T` 再开一个终端，然后加载环境：

~~~bash
cd /home/nvidia/l1_navigation
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 node list
ros2 topic list
~~~

有数据后，`ros2 topic list` 会列出导航、点云、里程计和地图相关话题。想看某个话题有没有持续更新，可以运行：

~~~bash
ros2 topic hz /Odometry
~~~

等到终端打印频率后，按 `Ctrl+C` 停止这项检查；这不会停止第一个终端里的导航。

### 5. 选择双轮或全向轮底盘

启动脚本默认选择双轮（`two_wheel`）参数。若机器人使用全向轮，在 `start_nav2.sh` 或 `start_map_navigation.sh` 命令里加 `chassis_model:=omni`，脚本会选择对应的全向 Nav2 参数文件。`chassis_model` 负责选择运动模型；`enable_chassis` 是独立的 CAN 底盘启动开关。第一次验证软件链时仍应使用 `enable_chassis:=false`。

无图导航，全向轮示例：

~~~bash
./tool/start_nav2.sh \
  chassis_model:=omni \
  config_file:=mid360.yaml \
  sensor_height:=0.25 \
  visualize:=true \
  enable_chassis:=false
~~~

双轮底盘省略 `chassis_model` 即可，也可显式设置 `chassis_model:=two_wheel`。已有 PCD 地图时，全向轮示例见[已有地图导航](使用手册.md#map-navigation)。

### 6. 真车运行

只有负责硬件的人已经确认 CAN 接口处于启用状态、通信速率正确、急停能立即停车、速度标定正确，并且测试区域清空后，才可以把 `enable_chassis:=false` 改为 `enable_chassis:=true`。真车示例：

~~~bash
./tool/start_nav2.sh config_file:=mid360.yaml sensor_height:=0.25 visualize:=true enable_chassis:=true
~~~

脚本不会替你设置 CAN。CAN 检查失败时先停下处理接口，不要通过删除参数或绕过检查来继续。

### 7. 停止

回到第一个终端按 `Ctrl+C`，等待启动脚本和节点退出，再启动建图或地图导航。

### 8. 常见情况

- **RViz 没打开**：确认这台电脑有图形桌面，命令里的 `visualize:=true` 没有拼错；无显示器时改成 false。
- **没有点云或里程计**：按[传感器处理流程](传感器建图与校准.md#sensor-check)检查雷达和网卡，不要先改 Nav2 参数。
- **启动后马上退出**：查看终端最早出现的错误，再检查 `logs/start_nav2_*.log`。不要只看最后一行自动重启提示。
- **CAN 报错**：使用 `enable_chassis:=false` 只检查软件链；真实底盘需要硬件负责人配置和检查 CAN。

## 已有地图导航

这条流程适用于已经有静态 PCD 地图的情况。程序会先把 PCD 转成导航需要的地图文件，再用雷达确认机器人在地图中的位置，位置确认后才启动导航。
RViz 的 map 坐标系、Nav2 Goal 工具、代价显示和诊断面板见[RViz 界面与导航操作](Nav2导航与RViz操作.md#rviz-guide)。

### 1. 开始前检查

1. 确认地图文件存在。若使用前一页刚生成的地图，文件应是 `PCD/clean_map.pcd`。
2. 确认 MID360 已接好，且按[传感器流程](传感器建图与校准.md#sensor-check)能看到点云和里程计。
3. 确认没有另一条导航、定位或建图流程仍在运行。本启动脚本会处理已知的残留导航进程。
4. 第一次只看定位和规划时，务必关闭底盘。不要省略 `enable_chassis:=false`。

先检查地图文件：

~~~bash
cd /home/nvidia/l1_navigation
ls -lh PCD/clean_map.pcd
~~~

如果显示“没有那个文件”，请回到[建图并保存地图](传感器建图与校准.md#mapping-save)完成建图，或把下一个命令里的路径换成已有 PCD 的位置。

### 2. 第一个终端：启动地图导航

在同一个终端、仍处于仓库根目录时运行：

~~~bash
./tool/start_map_navigation.sh \
  pcd_file:=PCD/clean_map.pcd \
  config_file:=mid360.yaml \
  visualize:=true \
  enable_chassis:=false
~~~

这里的 `PCD/clean_map.pcd` 是从仓库根目录开始的相对路径。如果你的仓库不在 `/home/nvidia/l1_navigation`，先按实际位置进入仓库目录再运行。

默认使用双轮配置。全向轮配置只需在启动参数中加入 `chassis_model:=omni`：

~~~bash
./tool/start_map_navigation.sh \
  chassis_model:=omni \
  pcd_file:=PCD/clean_map.pcd \
  config_file:=mid360.yaml \
  visualize:=true \
  enable_chassis:=false
~~~

脚本会自动读取仓库中的 `src/bringup/config/nav2_map_navigation_omni.yaml`；省略 `chassis_model` 时继续使用双轮默认配置。目标电脑上的仓库也必须包含对应的全向参数文件。

### 3. 等待地图转换和自动定位

第一次使用某张地图时，程序会在 `PCD/clean_map_nav/` 下生成导航所需的二维地图、地形数据和定位点云。首次转换需要等待一会；以后地图和参数都没变时会复用这些文件。转换期间查看终端进度，不要重复启动第二份。

接着会打开定位画面并自动搜索机器人在 PCD 中的位置。默认不需要你手工设置初始位姿。定位期间终端可能会显示搜索、匹配或质量检查信息；还没通过前不要发目标。确认成功时，日志会出现类似下面的英文原文：

~~~text
[*] Fresh localization handoff received; closing GICP RViz and enabling navigation RViz
[*] Localization handoff is ready; NavigationGate may now activate Nav2
[*] Map navigation is starting; lifecycle logs will report Nav2 activation and readiness
~~~

意思是定位结果已交给导航，程序正在打开导航阶段。定位画面会关闭或切换，导航 RViz 接着显示。若只看到 `Starting map navigation gate...` 而始终没有上面这些成功信息，说明定位还没完成，不要发送目标。

在定位确认之前：

- 不要在 RViz 点击导航目标。
- 不要把 <code>enable_chassis:=false</code> 改成 true。
- 如果长时间没有定位确认，按下方故障排查步骤检查，不要反复重启。

### 4. 在地图上发送一个目标

确认导航画面已经打开、地图显示正常、诊断面板没有定位失效/导航暂停，并且终端显示导航阶段启动后，再试发目标：

1. 在 RViz 顶部工具栏选择 `Nav2 Goal`（导航目标）工具。
2. 在地图上想去的位置单击并按住鼠标，拖出机器人到达后应朝向的方向。
3. 松开鼠标。RViz 应显示规划路线；导航诊断面板的规划和任务执行状态应随当前目标更新。

第一次练习请把目标选在地图上距离机器人较近、路线清楚的位置。只要底盘参数为 false，目标只用于检查定位和规划，不会驱动车辆。若状态面板报告目标受阻、路径失败或导航暂停，查看面板最近警告和启动终端日志；不要反复发送同一目标。

### 5. 停止导航

回到第一个终端按 `Ctrl+C`，等待脚本结束并清理本次启动的节点和定位程序，再启动其他流程。

### 6. 地图更新后重新生成缓存

如果 PCD 内容变了但仍使用相同文件名，或你改了地图转换参数，可手动要求重建缓存：

~~~bash
./tool/start_map_navigation.sh \
  pcd_file:=PCD/clean_map.pcd \
  rebuild_map:=true \
  visualize:=true \
  enable_chassis:=false
~~~

重建会花更长时间。普通重复启动不用加 `rebuild_map:=true`。

### 7. 常见问题

- **提示找不到 PCD**：检查当前目录是否为仓库根目录，再运行 `ls -lh PCD/clean_map.pcd`；也可使用完整地图路径。
- **第一次启动等待较久**：通常是在生成地图缓存。看终端是否还在打印转换进度，不要另开第二份。
- **定位窗口开着但一直没交接**：检查雷达是否有点云、地图是否对应当前场地、雷达配置是否与建图时一致。没有确认前不要发目标。
- **终端提示 CAN 配置失败**：检查命令里是否保留 `enable_chassis:=false`。不要为了只看地图而配置或启动底盘。
- **RViz 里的地图看起来偏了**：先停止运行，确认使用的是正确 PCD 和雷达外参。不要在错位地图上启动真车导航。

## RViz 界面与导航操作

RViz 用来查看点云、地图、机器人位置和规划结果，并通过目标工具向 Nav2 发送导航目标。只在相应导航流程已启动且状态允许时发送目标。第一次打开时保持 `enable_chassis:=false`，这样可以检查软件链而不向底盘发送控制。

### 1. 两种导航画面的区别

| 项目 | 无图导航 | 已有地图导航 |
| --- | --- | --- |
| 启动流程 | [无图实时导航](Nav2导航与RViz操作.md#no-map-navigation) | [已有地图导航](Nav2导航与RViz操作.md#map-navigation) |
| Fixed Frame | `odom` | `map` |
| 地图来源 | 当前运行期间的在线感知与融合 | 输入 PCD 转换生成的静态地图，并叠加在线数据 |
| 定位就绪条件 | 传感器、在线地图和导航门控状态正常 | 必须看到定位交接成功并进入导航阶段 |
| 主要显示 | 当前地面/结构点云、历史点云、路径、机器人 footprint | 静态地图、定位点云、在线地面/结构点云、路径和代价信息 |

RViz 左侧 **Displays** 列出显示项。点显示项左边的复选框可暂时隐藏该图层；如果关闭了必要图层，可重新勾选或重启流程恢复默认配置。无图模式不加载已有 PCD；不要把 RViz 中的历史点云显示当作已保存的独立地图文件。

### 2. 先检查导航面板

默认 RViz 包含 Nav2 操作面板和“导航诊断”面板。诊断面板显示的信息包括：

- **导航门控**：导航当前是否允许启动或继续；若暂停，会显示暂停原因。
- **任务执行**：当前目标的执行、局部路径恢复、到达、取消或失败状态。
- **定位**：FAST-LIO 或地图定位健康状态是否新鲜。
- **实时障碍**：最近障碍点云是否到达、更新时间和点数。
- **规划**：当前目标的规划结果；拒绝时可能显示目标附近的原因。
- **目标管理**：目标是等待、路由、航点执行还是已结束。
- **前沿探索**：无图导航启用探索时的进度或结束状态；未启用时显示未启用。
- **地图保存**：地图融合保存按钮及操作响应。
- **最近警告/错误**：保留最近的诊断日志。出现暂停或失败时先阅读这里和启动终端，不要反复点击目标。

状态面板显示“等待”通常表示对应数据尚未到达，不能单凭 RViz 窗口已打开就认为导航就绪。地图导航还要等终端出现定位 handoff 成功信息；具体判据见[地图导航流程](Nav2导航与RViz操作.md#map-navigation)。

### 3. 识别地图、障碍和路径

- **机器人 footprint**：机器人当前在地图中的占地边界。它与点云位置不一致时，先停止并检查 TF、定位或雷达外参。
- **全局路径**：从机器人到目标的整体路线；默认显示为黄色线。
- **局部路径**：控制器当前正在跟随的路线；默认显示为绿色线。
- **代价显示**：地图导航中蓝到红表示障碍膨胀代价，青色表示机器人内切禁区，紫色表示致命障碍。代价层是规划输入的可视化，仍应结合原始点云和现场环境判断。
- **地面/结构点云**：当前可见区域的地面与结构显示。无图模式还提供有界历史显示；历史显示用于观察运行过程，不能替代 PCD 保存操作。
- **地图**：地图导航显示输入 PCD 转换得到的导航地图。若 PCD 与现场不匹配或地图和雷达点云明显错位，停止导航并检查地图、IP/传感器配置和外参。

少数调试图层默认关闭。需要排查时，可在 Displays 中启用 costmap、GridMap 或原始点云；这些图层数据较多，普通运行不需要全部打开。

### 4. 发送导航目标

确认诊断面板没有显示定位失效或导航暂停，并确认点云/地图与机器人位置合理后再发送目标：

1. 在顶部工具栏选择 `Nav2 Goal`（导航目标）工具。该工作区的 RViz 配置使用 Nav2 GoalTool。
2. 在当前可通行区域内单击目标位置，按住鼠标拖出机器人到达后应朝向的方向，再松开。
3. 观察全局路径和局部路径是否出现，并查看“任务执行”和“规划”状态。
4. 无图导航可能在在线已知区域规划，或按当前导航配置处理尚未观测区域；如果状态显示路由/等待观测/受阻，先读面板原因，不要连续重复派发目标。
5. 地图导航应先确认地图上目标位置正确且定位已通过。首次测试选近处、路线清楚的目标。

发送目标只会验证定位和规划的前提是 `enable_chassis:=false`。如果底盘已启用，发送目标可能让机器人移动；这时先确认周边清空、急停可用，并由负责人员监护。

### 5. 停止或取消

- 停止整条导航链：回到启动流程的终端按 `Ctrl+C`，等待程序和脚本清理退出。
- 取消当前目标：使用 Nav2 操作面板中的取消操作，并确认诊断面板显示目标已取消或执行停止。取消目标不会关闭导航节点。
- 只关闭 RViz 窗口不会可靠地停止启动终端中的所有 ROS 节点；结束流程仍应在启动终端按 `Ctrl+C`。

### 6. 保存在线融合地图

导航诊断面板提供“保存融合地图”按钮，也支持 `Ctrl+R`。点击后观察“地图保存”状态，确认响应报告成功和输出路径后，再检查文件是否存在。保存功能对应当前导航链提供的融合地图服务；它与建图流程中的 `/map_save`、`/static_map_save` 不是同一入口。保存文件用途和路径以面板返回信息及[运行日志](数据录制与问题排查.md#troubleshooting)为准。

### 7. 画面或目标异常时

| 现象 | 先检查 |
| --- | --- |
| RViz 报 Fixed Frame 错误或画面空白 | 确认流程运行、Fixed Frame 与流程相符（无图 `odom`，地图导航 `map`），再看 TF 和话题 |
| 看不到雷达点云 | 检查 `/livox/lidar` 频率、Livox 驱动日志和网口，见[MID360 网络配置](设备接入与启动配置.md#mid360-network) |
| 地图与点云错位 | 停止导航，核对 PCD 场地、MID360 配置和外参，不要在错位画面上启用底盘 |
