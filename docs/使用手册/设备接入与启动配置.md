# 设备接入与启动配置

MID360 接线、电脑网口、Livox 驱动网络字段和 ROS 2 启动配置都集中在本页。首次接入请先完成 [MID360 网络配置](#mid360-network)，日常启动使用[README 总入口](../../README.md#user-manual-index)中的任务流程和 `tool/` 命令。

## 日常使用与参数查询

日常优先使用工作流页面里的启动脚本。需要查当前 ROS 2 launch 参数时，在已加载 ROS 和工作区环境的终端运行：

```bash
ros2 launch bringup nav2_theta_teb.launch.py --show-args
```

需要查询其他启动文件时，替换示例中的文件名。参数会随工作区版本变化；本页列出用途和常见参数，完整默认值以当前代码和 `--show-args` 为准。直接调用底层 launch 时，先确认对应流程的前置检查已完成。

<a id="mid360-network"></a>

## MID360 接线、电脑网口与驱动配置

本页从物理连接开始，完成电脑以太网配置、地址检查和 Livox 驱动配置。示例使用仓库现有配置中的 MID360 地址；开始前必须核对现场雷达地址，不能把示例地址当作每台设备的出厂地址。

### 先分清两个 IP 地址

连接雷达需要配置两端：**雷达有自己的 IP，电脑上接雷达的以太网网卡也有自己的 IP**。两者在同一子网内，但不能相同。只改 Ubuntu 网卡不会改变雷达自己的地址。

当前仓库 `src/livox_ros_driver2/config/MID360_config.json` 的配置示例如下：

| 设备 | 示例 IPv4 | 子网掩码 | 说明 |
| --- | --- | --- | --- |
| MID360 | `192.168.1.194` | `255.255.255.0`（`/24`） | 以现场设备记录或 Livox 设备配置工具中读到的地址为准 |
| Ubuntu 电脑的雷达网口 | `192.168.1.5` | `255.255.255.0`（`/24`） | 选择同一网段中未被其他设备使用的地址 |

```text
MID360 网络口  ───── 以太网线 ─────  Ubuntu 专用有线网口
192.168.1.194/24                     192.168.1.5/24
```

如果雷达地址是 `192.168.1.194`，电脑可以用 `192.168.1.5/24`；不要把电脑和雷达都设成 `192.168.1.194`。若现场地址不同，以下命令和 JSON 示例都要换成实际地址。

### 1. 接线并找到电脑上的物理网口

1. 关闭或停止当前正在运行的雷达、建图和导航程序。
2. 按 MID360 设备说明接好电源。用以太网线把雷达的网络口接到电脑**专用的有线网口**。有多个网口时，记录插入网线的那个网口；不要根据 `enp...` 名字猜它是哪一个。
3. 如果电脑有 Wi-Fi 或另一张网卡用于上网，保留它原来的设置；本页只配置连接雷达的网卡。直连时先不要把雷达口接到一个地址规划不明的办公网络或路由器。
4. 打开终端查看设备名和连接状态：

   ```bash
   ip -br link
   nmcli device status
   ```

   忽略 `lo`。找到有线接口（例如 `enp3s0`、`eno1`）；`nmcli device status` 的 `TYPE` 应为 `ethernet`。在 `ip -br link` 的接口状态中看到 `LOWER_UP` 通常表示网线物理链路已接通。NetworkManager 在设置静态地址之前可能仍把连接列为未连接，先记下设备名和对应连接配置名。若没有物理链路，检查雷达供电、网线、转接器和网口指示灯。

### 2. 先确认雷达地址

从设备标签、现场网络记录或负责配置 MID360 的人员处确认雷达 IP。仓库示例是 `192.168.1.194`，但雷达曾被改过地址时就不一定相同。

如果需要改雷达自身的 IP，请使用现场批准的 Livox 设备配置方式，修改后记录生效的雷达 IP 并重新确认。**Ubuntu 的“有线网络”页面配置的是电脑网卡，不是雷达。** 不确定设备配置工具或当前雷达地址时，先不要尝试随机 IP。

记录本次使用的两项值：

```text
雷达 IP：      例如 192.168.1.194
电脑网口 IP：  例如 192.168.1.5
子网掩码：     255.255.255.0（前缀 /24）
```

电脑地址要和雷达处于同一子网、最后一段不同，并确认未被其他设备占用。

### 3. 在 Ubuntu 图形界面给雷达网口配置静态 IPv4

这是推荐方式，便于在界面里确认你正在设置哪张网卡：

1. 打开 Ubuntu **设置 → 网络**。
2. 在“有线”区域找到刚才接入雷达的网卡，点右侧齿轮。可以参照网卡设备名确认，不要改 Wi-Fi 或另一张上网网卡。
3. 打开 **IPv4** 标签，把方式从“自动（DHCP）”改为“手动”。
4. 添加一行电脑地址。若雷达是 `192.168.1.194`，且现场确认电脑可用地址为 `192.168.1.5`，填写：

   | 界面字段 | 示例值 |
   | --- | --- |
   | 地址 | `192.168.1.5` |
   | 子网掩码 | `255.255.255.0` |
   | 网关 | 留空 |
   | DNS | 留空 |

   与雷达直连时通常不需要网关或 DNS；如果电脑网口经过受管网络或现场网络管理员给了专用设置，按该网络规划填写。
5. 点击 **应用**。必要时把该有线连接断开再连接一次。
6. 回到终端检查地址：

   ```bash
   ip -br addr
   ```

   在刚才记录的网卡那一行应看到类似 `192.168.1.5/24`。`/24` 等于子网掩码 `255.255.255.0`。如果地址显示在另一张网卡上，返回网络设置改正确的接口。

### 4. 可选：用命令行配置静态地址

推荐给雷达网口建立一个独立的 NetworkManager 配置，按接口设备名绑定，避免改错 Wi-Fi 或其他以太网连接。先查设备名：

```bash
nmcli device status
ip -br link
```

假设接雷达的接口名是 `enp3s0`、MID360 地址是 `192.168.1.194`，且电脑地址 `192.168.1.5` 已确认未被占用，运行：

```bash
sudo nmcli connection add type ethernet \
  ifname enp3s0 \
  con-name livox-mid360 \
  ipv4.method manual \
  ipv4.addresses 192.168.1.5/24 \
  ipv4.never-default yes \
  connection.autoconnect yes \
  connection.autoconnect-priority 100
sudo nmcli connection up livox-mid360
ip -br addr show dev enp3s0
ip route get 192.168.1.194
```

把 `enp3s0` 换成 `nmcli device status` 中实际接雷达的接口名；按现场地址替换电脑 IP 和雷达 IP。地址配置会在重启后保留。直连雷达不需要网关或 DNS；`ipv4.never-default yes` 会避免该接口成为电脑的默认上网路由。若 `livox-mid360` 配置名已存在，不要重复添加，改用已有配置名执行 `nmcli connection modify`。配置后应在接口行看到 `192.168.1.5/24`，路由查询应显示 `dev enp3s0 src 192.168.1.5`。

如果 `livox-mid360` 配置已经存在，用下面命令更新它（同样替换接口名和地址）：

```bash
sudo nmcli connection modify livox-mid360 \
  connection.interface-name enp3s0 \
  ipv4.method manual \
  ipv4.addresses 192.168.1.5/24 \
  ipv4.never-default yes \
  connection.autoconnect yes \
  connection.autoconnect-priority 100
sudo nmcli connection up livox-mid360
```

### 5. 验证电脑到雷达的路由和连通性

先确认发往雷达地址的数据会走正确的网卡，且源地址是刚设置的电脑网口地址：

```bash
ip route get 192.168.1.194
```

把示例 IP 换成真实雷达地址。输出应包含连接雷达的接口（例如 `dev enp3s0`）和对应的电脑地址（例如 `src 192.168.1.5`）。若显示走 Wi-Fi 或其他接口，通常是网卡选错、子网冲突或路由配置不匹配；先修正网络，再启动驱动。

尝试 ping 雷达：

```bash
ping -c 4 192.168.1.194
```

收到 `bytes from ...` 表示有网络回应。若超时，逐项确认雷达供电、网线、接口状态、两端 IP/掩码，以及 `ip route get` 的接口和源地址。部分设备可能不回应 ping，因此 ping 失败本身不能证明雷达坏了；后续还要看驱动日志和 ROS 点云话题。

### 6. 把两端地址写入 Livox 驱动配置

仓库 MID360 ROS 2 launch 读取 `src/livox_ros_driver2/config/MID360_config.json`。先备份，再编辑：

```bash
cd /home/nvidia/navigation
cp src/livox_ros_driver2/config/MID360_config.json \
   src/livox_ros_driver2/config/MID360_config.json.bak
nano src/livox_ros_driver2/config/MID360_config.json
```

在文件中按下表填写同一组地址：

| JSON 字段 | 应填写的内容 | 示例 |
| --- | --- | --- |
| `MID360.host_net_info[0].host_ip` | 电脑的雷达网口 IP | `192.168.1.5` |
| `MID360.host_net_info[0].lidar_ip` | MID360 的 IP 列表 | `192.168.1.194` |
| `lidar_configs[0].ip` | 同一台 MID360 的 IP | `192.168.1.194` |

`lidar_ip` 是数组；保留方括号和引号。文件里雷达 IP 出现多次时必须一致。只改确认过的 IP，不要顺手更改端口、`pcl_data_type` 或外参。

在 `nano` 中按 `Ctrl+O`、回车保存，再按 `Ctrl+X` 退出。如果系统没有 `nano`，可用 Ubuntu 的文本编辑器打开同一路径；保留 JSON 的引号、逗号和方括号，不要用文字处理软件编辑。检查 JSON 语法：

```bash
python3 -m json.tool \
  src/livox_ros_driver2/config/MID360_config.json >/dev/null \
  && echo 'JSON 格式正确'
```

只有看到 `JSON 格式正确` 才继续。若格式报错，可恢复刚才的备份：

```bash
cp src/livox_ros_driver2/config/MID360_config.json.bak \
   src/livox_ros_driver2/config/MID360_config.json
```

驱动从已安装的 ROS 包目录读取配置。改完 JSON 后，在仓库根目录重新构建驱动包，再加载工作区环境：

```bash
cd /home/nvidia/navigation
source /opt/ros/humble/setup.bash
colcon build --packages-select livox_ros_driver2
source install/setup.bash
```

仓库若位于其他位置，先进入实际仓库根目录。完整安装步骤见[原生环境安装与编译](环境准备与终端操作.md)。

### 7. 启动驱动并确认点云

停止旧的传感器流程后，在仓库根目录启动传感器链：

```bash
./tool/start_board.sh config_file:=mid360.yaml visualize:=false
```

另开一个终端，加载环境并逐项检查：

```bash
cd /home/nvidia/navigation
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 node list
ros2 topic list
ros2 topic hz /livox/lidar
```

应能看到 Livox 驱动节点、`/livox/lidar` 和 `/livox/imu`；FAST-LIO 启动正常后还应有 `/Odometry`。`ros2 topic hz /livox/lidar` 应持续打印频率。启动完整步骤见[传感器处理流程](传感器建图与校准.md#sensor-check)。

### 常见问题

| 现象 | 优先检查 |
| --- | --- |
| `ip -br addr` 中没有雷达网口 | 网线、转接器、网口状态；运行 `nmcli device status` 核对接口 |
| 雷达和电脑 IP 看起来在同一网段但没有回应 | 子网掩码、地址冲突、雷达实际地址、网线和供电 |
| `ip route get` 显示 Wi-Fi 或错误网卡 | 电脑地址冲突或路由重叠；确保命令从专用雷达网口发送 |
| ping 通但 `/livox/lidar` 没数据 | 核对 JSON 三处 IP、驱动启动日志、型号对应的 launch；ping 只验证网络，不验证 ROS 驱动 |
| 有 `/livox/lidar`，没有 `/Odometry` | 检查 `mid360.yaml` 中的 `lid_topic`、`imu_topic` 和 FAST-LIO 日志 |
| 改过 JSON 但启动仍使用旧地址 | 停止旧节点、重新构建驱动包、重新 source 工作区，并确认配置文件已安装到当前工作区 |

不要同时运行两份 Livox 驱动。网络和驱动都检查通过后，再回到[README 总入口](../../README.md#user-manual-index)选择建图或导航流程。

## 雷达点云地面与高程启动配置

### 用途

MID360 驱动、FAST-LIO、Patchwork++、FastDEM 和可选 RViz 的组合链。<code>tool/start_board.sh</code> 使用它；Nav2 快捷启动也会复用同一传感器处理链。

### 手动运行

~~~bash
ros2 launch bringup livox_fastlio_patchwork.launch.py config_file:=mid360.yaml visualize:=false
~~~

### 常用参数

- <code>config_file</code>：FAST-LIO YAML，默认 <code>mid360.yaml</code>。
- <code>cloud_topic</code>：Patchwork++ 输入，默认 <code>/cloud_registered_body</code>。
- <code>base_frame</code>：分割结果使用的坐标系，默认 <code>base_link</code>。
- <code>sensor_height</code>：base_link 离地高度，默认 0.25 m。
- <code>visualize</code>：是否启动 RViz，默认 true。
- <code>enable_fastdem</code>：是否启动 FastDEM，默认 true。
- <code>enable_static_map_filter</code>：是否启动时序静态过滤器，默认 false。
- <code>body_to_base_x/y/roll/pitch/yaw</code>：机身到 base_link 的外参。

过滤器默认把结果写入 clean_map.pcd。在同一台电脑上运行多条流程时，不要重复启动传感器节点。

<a id="fastlio-launch"></a>

## 雷达 FAST-LIO 完整启动配置

### 用途

组合启动 MID360 驱动、FAST-LIO 和可选静态地图过滤节点。建图包装脚本使用它，并向 FAST-LIO 传入原始地图路径。

### 手动运行

~~~bash
ros2 launch bringup livox_fastlio_bringup.launch.py config_file:=mid360.yaml map_file_path:=/absolute/path/raw_map.pcd
~~~

### 关键参数

- <code>config_file</code>：FAST-LIO YAML，默认 mid360.yaml。
- <code>map_file_path</code>：FAST-LIO <code>/map_save</code> 的 PCD 文件路径。
- <code>visualize</code>：是否打开 FAST-LIO 的 RViz，默认值为 true（打开）。
- <code>enable_static_map_filter</code>：是否启用时序体素过滤，默认值为 false（关闭）；<code>start_fastlio_mapping.sh</code> 默认会开启。
- <code>static_map_file</code>：过滤后的 PCD 保存路径。

它不会启动 Patchwork++、FastDEM 或 Nav2。要查看全部参数，运行 <code>ros2 launch bringup livox_fastlio_bringup.launch.py --show-args</code>。

<a id="headless-launch"></a>

## 无界面雷达 FAST-LIO 启动配置

### 用途

无图形界面的 FAST-LIO 建图组合入口，支持静态地图过滤的可选参数。适合无显示板卡或由外部进程管理 ROS 的部署。

### 手动运行

~~~bash
ros2 launch bringup livox_fastlio_headless.launch.py config_file:=mid360.yaml
~~~

此启动文件默认使用 mid360.yaml，静态过滤器默认关闭，也不会打开 RViz。要启用过滤器，还要设置 <code>enable_static_map_filter</code> 及对应的输出路径和参数。

当前推荐的传感器+地面链入口是 <code>tool/start_board.sh</code>；它默认无图并额外启动 Patchwork++ 和 FastDEM。

<a id="no-map-launch"></a>

## Theta* 与 TEB 导航启动配置

### 用途

运行不加载静态地图的在线导航链。FAST-LIO 和地面/高程感知使用 odom 滚动坐标；全局规划器 Theta*，局部控制器 TEB。

### 手动运行

~~~bash
ros2 launch bringup nav2_theta_teb.launch.py config_file:=mid360.yaml visualize:=true enable_chassis:=false
~~~

### 常用参数

- <code>config_file</code>：FAST-LIO 配置。
- <code>sensor_height</code>：base_link 离地高度，米。
- <code>visualize</code>：RViz 开关。
- <code>enable_chassis</code>：CAN 底盘开关，当前默认值为 true（启用）。
- <code>can_interface</code>：CAN 接口名，默认 can3。
- <code>use_sim_time</code>：是否使用仿真时钟。

第一次只查看数据时必须显式传 <code>enable_chassis:=false</code>。这个启动配置包含真实机器人控制链，但不会替你配置 CAN 网络接口。

<a id="map-launch"></a>

## 地图导航启动配置

### 用途

加载 PCD 转换生成的二维占据图和 2.5D 地形数据，启动地图导航、NavigationGate、局部感知和 Nav2。地图导航一键脚本另外管理 FAST-LIO 和定位阶段，因此推荐从 <code>tool/start_map_navigation.sh</code> 启动完整流程。

### 手动运行限制

直接调用时需要提供同一地图版本对应的 <code>map_yaml</code>、<code>terrain_map_file</code>、PCD 地图来源编号和导航保存根目录。漏传或混用文件会让地图信息对不上；不熟悉这些参数时，使用一键启动脚本。

### 常见参数

- <code>map_yaml</code>：Nav2 占据栅格 YAML。
- <code>terrain_map_file</code>：静态 2.5D 地形 NPZ。
- <code>sensor_height</code>：离地高度，默认 0.25 m。
- <code>visualize</code>：导航 RViz，默认 true。
- <code>enable_chassis</code>：底盘，默认 true。
- <code>publish_initial_pose</code> 和 <code>initial_pose_x/y/yaw</code>：可选人工地图坐标初始位姿。
- <code>enable_frontier_exploration</code>：自动前沿探索，默认关闭。

在桌面上检查时必须设置 <code>enable_chassis:=false</code>。启动文件会检查状态管理和定位数据是否足够新；手动启动还要保证地图与定位交接使用同一版本。

<a id="gicp-launch"></a>

## GICP 重定位启动配置

### 用途

读取 PCD 地图，运行 Livox、FAST-LIO、3D-BBS 粗定位、small_gicp 精定位和可选定位 RViz。定位结果经质量门控后交给 map-to-odom authority。

### 推荐入口

~~~bash
./tool/start_gicp_relocalization.sh pcd_file:=/absolute/path/clean_map.pcd visualize:=true
~~~

### 常见参数

- <code>pcd_file</code>：地图绝对路径。
- <code>registration_voxel_size</code>：配准地图体素，默认 0.20 m。
- <code>display_voxel_size</code>：仅显示用体素，默认 0.10 m。
- <code>num_threads</code>、<code>max_iterations</code>：配准资源和迭代配置。
- <code>tracking_frequency_hz</code>：首次定位后持续匹配频率。
- <code>offline_snapshot_dir</code>：可选离线输入快照输出目录。
- <code>enable_handoff</code>：是否由此启动配置负责发布 map 到 odom 的定位变换。

一键地图导航会自行编排 stage、handoff 和进程生命周期；手工运行时不要与它同时启动 GICP 或 handoff authority。

<a id="navigation-core-launch"></a>

## 导航核心启动配置

### 用途

启动地图导航的 FAST-LIO 和 map-to-odom handoff authority。它属于完整地图导航链的内部定位核心，通常由 <code>tool/start_map_navigation.sh</code> 管理。

### 常见参数

- <code>config_file</code>：FAST-LIO 配置。
- <code>handoff_topic</code> 和 <code>handoff_ready_topic</code>：定位交接目标和 ready 状态。
- <code>navigation_pause_request_topic</code>、<code>navigation_pause_status_topic</code>：与 NavigationGate 确认暂停。
- <code>handoff_smoothing_time_constant_sec</code>：map->odom 平滑时间常数。
- <code>handoff_max_translation_speed_mps</code>、<code>handoff_max_rotation_speed_deg_s</code>：TF 修正速度上限。

除非在维护导航架构，不要单独启动此核心。重复运行会造成多个 TF authority 争用。

<a id="calibration-launch"></a>

## 校准机身到 base_link 启动配置

### 用途

启动 IMU 重力方向校准节点，可选 FAST-LIO。默认采样 200 帧，不启动 Nav2。

~~~bash
ros2 launch bringup calibrate_body_to_base.launch.py sample_count:=200
~~~

机器人必须在水平地面上保持静止。常用参数为 <code>sample_count</code>、<code>timeout_sec</code>、<code>gyro_threshold</code> 和 <code>use_fast_lio</code>。<code>publish_body_to_base_tf</code> 默认临时发布 body 到 base_link 的 TF。

优先使用 <code>tool/calibrate_body_to_base.sh</code>，它会检查并加载工作区环境。

<a id="static-filter-launch"></a>

## 静态地图过滤启动配置

### 用途

只启动时序体素静态地图过滤节点，用于把 FAST-LIO 点云流分类为稳定地图和当前动态/拒绝点云。建图一键脚本已经会自动配置该节点，不要额外重复启动。

### 常见参数

- <code>enable_static_map_filter</code>：是否启用，默认 false。
- <code>static_map_file</code>：服务保存静态 PCD 的路径。
- <code>static_map_voxel_size</code>：体素大小，默认 0.18 m。
- <code>static_map_min_observations</code>：稳定确认所需观测数，默认 4。
- <code>static_map_min_duration</code>：候选最短观测时间。
- <code>static_map_confirmed_miss_limit</code>：活动地图动态清理 miss 帧数。
- <code>static_map_archive_min_duration</code> 与 <code>static_map_archive_min_origin_separation</code>：历史体素归档条件。

手工运行时需先保证 <code>/cloud_registered</code> 和 <code>/Odometry</code> 有输入；通过 <code>/static_map_save</code> 保存。

<a id="navigation-launch"></a>

## 实时导航完整启动配置

### 用途

这是 Nav2 标准启动配置的内部引用文件，为地图导航阶段提供状态管理器、Nav2 节点参数和启动选项。它通常由 map_navigation 启动文件调用，日常操作一般不需要直接启动它。

主要参数包括 namespace、use_sim_time、params_file、autostart、是否 composition、container_name、respawn 和 log_level。完整参数使用：

~~~bash
ros2 launch bringup nav2_navigation_launch.py --show-args
~~~

用户应从 <code>tool/start_map_navigation.sh</code> 或 <code>tool/start_nav2.sh</code> 启动对应流程，避免少传地图/定位上下文。
