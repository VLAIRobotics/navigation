# 传感器、建图与安装校准

相关操作步骤收在同一篇中，按下面的任务标题查找。

<a id="sensor-check"></a>

## 启动传感器处理链

这一步只启动传感器处理程序，不开导航，也不控制底盘。第一次运行时建议先走这条流程，确认雷达确实有数据，再继续建图或导航。

### 1. 启动前检查

先确认这些事情：

1. MID360 已通电，网线接在配置好的网口上。
2. 电脑的雷达网卡地址和雷达 IP 已按[网络配置说明](设备接入与启动配置.md#mid360-network)设置。
3. 没有另一个终端正在运行 `start_board.sh`、`start_nav2.sh` 或建图脚本。同一台电脑不要启动两份 Livox 驱动。
4. 已完成[原生环境安装和编译](环境准备与终端操作.md)。

### 2. 第一个终端：启动传感器处理链

按 `Ctrl+Alt+T` 打开终端，进入仓库根目录。若仓库不在 `/home/nvidia/l1_navigation`，把下面路径换成自己的实际路径：

~~~bash
cd /home/nvidia/l1_navigation
pwd
~~~

确认 `pwd` 显示的是仓库路径后，运行：

~~~bash
./tool/start_board.sh config_file:=mid360.yaml visualize:=false
~~~

这个脚本会自己加载 ROS 和工作区环境。`visualize:=false` 表示先不打开 RViz；`config_file:=mid360.yaml` 表示使用 MID360 对应的 FAST-LIO 配置。运行期间这个终端会持续显示信息，这是程序正在工作的正常现象，不要关闭它。

### 3. 第二个终端：检查雷达和处理结果

再按 `Ctrl+Alt+T` 打开另一个终端。每个新终端都需要单独加载环境：

~~~bash
cd /home/nvidia/l1_navigation
source /opt/ros/humble/setup.bash
source install/setup.bash
~~~

先查看当前有哪些 ROS 节点：

~~~bash
ros2 node list
~~~

再查看有哪些数据话题：

~~~bash
ros2 topic list
~~~

MID360 流程通常应能找到 `/livox/lidar`、`/livox/imu`、`/Odometry` 和地面分割相关话题。话题名称区分大小写，例如 `/Odometry` 中的 `O` 是大写。

用下面命令查看雷达是否持续发点云：

~~~bash
ros2 topic hz /livox/lidar
~~~

有数据时，稍等几秒会出现 `average rate` 一类的频率统计，并且数字会更新。按 `Ctrl+C` 只会停止这次频率查看，不会停止第一个终端里的传感器程序。可以再分别检查：

~~~bash
ros2 topic hz /Odometry
ros2 topic hz /patchworkpp/ground
~~~

每次先运行一条，看到频率后按 `Ctrl+C`，再查下一条。如果命令一直没有统计结果，表示该话题当前没有收到消息。

### 4. 如果需要看画面

先在第一个终端按 `Ctrl+C` 停掉当前流程，等它退出后再重新启动。不要在原流程还运行时再开一份：

~~~bash
cd /home/nvidia/l1_navigation
./tool/start_board.sh config_file:=mid360.yaml visualize:=true
~~~

这会在运行脚本的这台电脑打开 RViz。远程终端或没有图形桌面的电脑请继续用 `visualize:=false`。

### 5. 正常结束

回到第一个终端按 `Ctrl+C`，等待节点退出后，再启动其他传感器或导航流程。

### 6. 没有数据时先查这里

- `ros2 node list` 没有 Livox 节点：查看第一个终端最早出现的报错，以及 `logs/start_board_*.log`。
- 有 Livox 节点但没有 `/livox/lidar`：检查网线、网卡 IP、雷达 IP 和 [MID360 配置文件](设备接入与启动配置.md#mid360-network)。
- 有雷达点云但没有 `/Odometry`：确认 `mid360.yaml` 的输入话题和雷达型号相符，再查看 FAST-LIO 日志。
- `ros2` 提示找不到命令或程序包：在第二个终端重新执行三行环境加载命令。

## 建图并保存地图

这条流程会用 MID360 采集点云，并同时准备两份地图：一份保留 FAST-LIO 的原始累计点云，另一份经过时序过滤，尽量去掉移动物体。地图保存命令必须在建图仍运行时执行。

### 1. 开始前

- 先完成[传感器处理流程](传感器建图与校准.md#sensor-check)，确认雷达点云和里程计正常。
- 选择一个安全、允许移动机器人的区域。建图脚本不负责驱动底盘；请由现场人员安全地移动机器人或传感器。
- 检查 `PCD/` 里是否已经有同名地图。保存服务会覆盖同名输出文件；要保留旧地图，就给新地图换一个文件名。
- 建图期间不要同时启动其他雷达或 FAST-LIO 脚本。

### 2. 第一个终端：准备目录并启动建图

按 `Ctrl+Alt+T` 打开终端，进入仓库根目录：

~~~bash
cd /home/nvidia/l1_navigation
mkdir -p PCD
ls -ld PCD
~~~

`ls -ld PCD` 应显示这个目录。接着启动建图：

~~~bash
./tool/start_fastlio_mapping.sh \
  config_file:=mid360.yaml \
  map_save_file:=PCD/raw_map.pcd \
  map_file:=PCD/clean_map.pcd \
  rviz:=true
~~~

这里两个地图路径都相对于仓库根目录。脚本启动后会在终端打印实际绝对路径；检查路径确实位于本仓库的 `PCD/` 目录。

- `map_save_file` 是原始点云文件，名字设为 `raw_map.pcd`。
- `map_file` 是时序过滤后的静态地图，名字设为 `clean_map.pcd`。
- `rviz:=true` 会打开点云画面。没有图形桌面时改成 `rviz:=false`。

保持这个终端和 RViz 开着。沿需要建图的范围缓慢移动机器人，让传感器看见各个区域。静止时不会生成新的地图区域；移动太快或点云数据不稳定，也会影响地图质量。

### 3. 第二个终端：保存两份地图

采集完需要的区域后，不要先停掉建图。按 `Ctrl+Alt+T` 再开一个终端，加载环境：

~~~bash
cd /home/nvidia/l1_navigation
source /opt/ros/humble/setup.bash
source install/setup.bash
~~~

先保存 FAST-LIO 的原始累计点云：

~~~bash
ros2 service call /map_save std_srvs/srv/Trigger "{}"
~~~

等命令返回后，再保存经过静态过滤的地图：

~~~bash
ros2 service call /static_map_save std_srvs/srv/Trigger "{}"
~~~

两次响应都应包含 <code>success: true</code>。响应信息会说明保存结果；启动终端也会打印各自的输出路径。

| 文件 | 内容 | 通常怎么用 |
| --- | --- | --- |
| `PCD/raw_map.pcd` | FAST-LIO 累计的原始点云，未经过动态物体过滤 | 留档、排查原始数据 |
| `PCD/clean_map.pcd` | 过滤器根据多帧观测确认的静态点云 | 后续地图导航优先使用 |

静态地图需要机器人移动并观察环境一段时间，过滤器才能判断哪些点稳定。刚启动就保存，或只在原地采集，静态地图可能很稀疏。

### 4. 第三个检查：确认文件确实保存

仍在第二个终端运行：

~~~bash
ls -lh PCD/raw_map.pcd PCD/clean_map.pcd
~~~

应该能看到两个文件及各自的大小。若显示“没有那个文件”或大小为 `0`，先不要拿它导航；检查服务响应里的路径和保存错误。

### 5. 结束建图

确认两份文件存在之后，回到第一个终端按 `Ctrl+C`，等待启动程序退出。此时地图已保存到硬盘，关闭 RViz 不会删除它们。

### 6. 保存失败时先检查

- `ros2 service call` 提示找不到服务：建图可能已经退出，或静态过滤器没有启动。查看第一个终端和 `logs/start_fastlio_mapping_*.log`。
- 服务返回 `success: false`：看响应里的错误信息，检查 `PCD/` 是否可写、磁盘是否已满。
- 只保存出原始图：确认启动参数里写了 `map_file:=PCD/clean_map.pcd`，并且运行期间静态过滤器收到了点云。
- 文件有但很小或几乎空白：多采集一些区域，慢慢移动后重新保存；不要直接覆盖想保留的旧地图。

## 校准 IMU 安装角度

只有在雷达或底盘重新安装、安装角度发生变化，或已经确认姿态明显不对时才做。平时启动机器人不需要重复校准。

### 1. 采集前

1. 把机器人放在水平、坚硬的地面上。
2. 确认 MID360 已接通，网卡和 IP 配置正确。
3. 让机器人完全静止；不要有人扶着晃动，也不要在斜坡上采集。

### 2. 运行校准

按 `Ctrl+Alt+T` 打开终端，进入仓库根目录后运行：

~~~bash
cd /home/nvidia/l1_navigation
./tool/calibrate_body_to_base.sh
~~~

脚本会启动 Livox 驱动，等待 `/livox/imu` 上有 200 帧有效且判定为静止的数据。通常几秒内会完成。完成时终端会打印类似下面的参数：

~~~text
body_to_base_roll:=...
body_to_base_pitch:=...
body_to_base_yaw:=0.000000
~~~

数值里的省略号不是要输入的内容，实际输出会显示数字。脚本还会临时发布 `body` 到 `base_link` 的变换，方便其他节点查看校准效果；它不会替你修改任何 YAML 文件。

### 3. 采样失败怎么办

- 出现 `Vehicle moved during calibration`：机器人在采样时动了。按 `Ctrl+C` 停止，重新放平并静置后再运行。
- 超时或没有收到足够 IMU 帧：检查 `ros2 topic hz /livox/imu` 是否有数据，以及 MID360 网络配置。
- 输出角度与实物明显不符：不要直接写入配置。先确认地面水平、传感器固定牢靠，并找负责安装标定的人复核。

需要多采一些样本时，可以把数量增加到 300：

~~~bash
./tool/calibrate_body_to_base.sh sample_count:=300
~~~

默认陀螺静止阈值是 `0.05 rad/s`。不确定含义时不要随意调整。

### 4. 把结果写入配置

校准程序只打印结果，不会保存。确认数值可靠后，先备份再由熟悉配置的人把 `body_to_base_roll` 和 `body_to_base_pitch` 写入对应启动参数或 FAST-LIO 配置。不要把角度填进雷达自身的 `extrinsic_R`；那是另一组外参。
