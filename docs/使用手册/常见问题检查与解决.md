# 常见问题检查与解决

先按这一页从上往下查。不要遇到一个报错就连续重启所有程序；启动终端里最早出现的错误通常最有用。若你只是想查看某一项数据，可以先用 `enable_chassis:=false`，不要为了绕过报错启动车辆。

## 先做这四步

### 1. 看清楚报错出现在哪个终端

启动脚本的终端要保持开着。记录报错前后几行，特别是第一个红色或带 `ERROR` 的信息。若终端还在运行，不要先关掉窗口；另开终端做下面的检查。

### 2. 确认你在项目目录

~~~bash
cd /home/nvidia/nav2.0
pwd
ls
~~~

`pwd` 应显示项目目录，`ls` 应能看到 `src`、`tool` 和 `README.md`。如果仓库放在别处，把 `cd` 后的路径换成实际位置。

### 3. 在当前终端加载环境

每个新开的终端都要单独加载一次：

~~~bash
source /opt/ros/humble/setup.bash
source install/setup.bash
~~~

启动脚本通常会自己加载环境；手动运行 `ros2 topic`、`ros2 service` 或直接运行分析命令时，才需要自己输入这两行。如果 `install/setup.bash` 不存在，回到[环境准备与终端操作](环境准备与终端操作.md#install-build)完成编译。

### 4. 找到对应脚本的日志

~~~bash
cd /home/nvidia/nav2.0
ls -lt logs | head
~~~

忽略开头的 `total ...`，把列表中最新的真实文件名放到下面命令里：

~~~bash
tail -n 100 logs/这里换成列表里的真实文件名.log
~~~

`这里换成列表里的真实文件名.log` 是说明文字，不能原样输入。若不确定哪个日志对应启动命令，按文件名找 `start_board`、`start_nav2`、`start_map_navigation` 或 `start_fastlio_mapping`。

## 常见情况怎么查

### 终端说 `ros2: command not found`

在报错的同一个终端运行：

~~~bash
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 --help
~~~

如果 `source /opt/ros/humble/setup.bash` 报文件不存在，ROS 2 Humble 没安装好；如果第一行成功、第二行报文件不存在，项目还没有编译完成。分别回到[原生安装与编译](环境准备与终端操作.md#install-build)检查。

### 找不到 `bringup`、FAST-LIO 或 Livox 程序包

先重新加载环境，再查程序包是否已编译安装：

~~~bash
cd /home/nvidia/nav2.0
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 pkg list | grep -E 'bringup|fast_lio|livox_ros_driver2'
~~~

没有输出时，回到编译步骤确认命令是否以失败结束。编译成功后再运行 `source install/setup.bash`。不要只在另一个终端编译，却在当前终端忘了加载环境。

### 有 Livox 节点，但 `/livox/lidar` 没有数据

在新终端加载环境后运行：

~~~bash
ros2 node list
ros2 topic list
ip -br addr
nmcli device status
~~~

检查顺序：

1. 确认 MID360 已供电，网线插在电脑上配置过的有线网口。
2. 在 `ip -br addr` 里找到雷达网口，确认它有现场分配的地址；不要把 Wi-Fi 网卡当成雷达网口。
3. 对照 [MID360 接线与网络配置](设备接入与启动配置.md#mid360-network)，核对电脑 IP、雷达 IP，以及 `MID360_config.json` 里的 `host_ip`、`lidar_ip` 和 `lidar_configs` 地址。
4. 查看启动日志最早的 Livox 错误。改过 JSON 后需按网络配置页重新构建 Livox 驱动包，再停掉旧流程并重新启动。

可以用 `ping -c 4` 检查电脑是否收到雷达回应，但有些设备不回应 ping；ping 没回应不能单独证明雷达坏了，仍需检查驱动日志和 ROS 话题。

### 有点云，但 `/Odometry` 没有数据

先查看点云是否持续更新。每次只运行一条频率命令；等几秒钟，看到 `average rate` 后按 `Ctrl+C` 停止这项查看，再运行下一条。按 `Ctrl+C` 不会停止另一个终端中的启动程序。

~~~bash
ros2 topic hz /livox/lidar
~~~

然后分别检查 IMU 和里程计：

~~~bash
ros2 topic hz /livox/imu
~~~

~~~bash
ros2 topic hz /Odometry
~~~

确认点云和 IMU 有频率后，打开 `src/FAST_LIO_ROS2/config/mid360.yaml`，核对 `lid_topic`、`imu_topic` 是否分别对应驱动实际发布的话题。然后查看 FAST-LIO 启动日志中的首个错误。外参不确定时不要照抄另一台设备的值。

### RViz 打开了，但画面空白或没有机器人

1. 确认启动命令里使用了 `visualize:=true` 或 `rviz:=true`。
2. 在另一个终端运行 `ros2 topic list`，确认这条流程预期的话题存在；再用 `ros2 topic hz /livox/lidar` 检查点云是否在更新。
3. 有话题但 RViz 空白时，看启动终端是否报告 TF 或 Fixed Frame 错误。无图导航通常使用 `odom`，已有地图导航使用 `map`；不要把其他流程的 RViz 配置随便套过来。
4. 远程终端、没有桌面或显示服务未配置时，先用 `visualize:=false` 验证数据链。无界面时 RViz 不会在机器人主机上凭空显示到你的电脑。

### 地图保存命令提示找不到服务

`/map_save` 和 `/static_map_save` 只在建图流程运行期间提供。

- 第一个终端必须仍在运行 `./tool/start_fastlio_mapping.sh`，不能已经按过 `Ctrl+C`。
- 保存命令要在第二个终端输入；该终端先运行本页“加载环境”的两行命令。
- 原始地图调用 `/map_save`，过滤地图调用 `/static_map_save`。服务名称不要输反。
- 若只有一个服务存在，检查启动日志和 `enable_static_map_filter` 配置。

### 服务调用成功，但 PCD 不存在或文件大小为 0

先看服务响应中的 `message` 和建图启动时打印的实际保存路径。再检查：

~~~bash
cd /home/nvidia/nav2.0
ls -lh PCD/raw_map.pcd PCD/clean_map.pcd
df -h .
~~~

如果输出路径不同，用打印出来的路径检查文件。若磁盘空间不足，先保留现有地图，再清理确定不用的录制数据；不要删除 `src/`、`install/` 或还要使用的地图。

### 提示找不到 PCD，或地图导航一直没有完成定位

先确认地图路径和定位条件：

~~~bash
cd /home/nvidia/nav2.0
ls -lh PCD/clean_map.pcd
~~~

如果 PCD 在其他位置，把启动参数 `pcd_file:=PCD/clean_map.pcd` 换成实际文件位置。程序第一次转换地图时需要等一段时间；转换完成后还会搜索定位。定位交接成功前不要点击 Nav2 Goal，也不要打开底盘。长时间未交接时，核对地图是否来自当前场地、雷达点云是否正常，以及 MID360 配置和安装外参是否与建图时一致。

### 出现 CAN 接口错误

只检查 RViz、定位或软件规划时，在对应的完整导航命令中明确设置 `enable_chassis:=false`。无图导航的例子：

~~~bash
cd /home/nvidia/nav2.0
./tool/start_nav2.sh config_file:=mid360.yaml sensor_height:=0.25 visualize:=true enable_chassis:=false
~~~

已有 PCD 地图导航的例子：

~~~bash
cd /home/nvidia/nav2.0
./tool/start_map_navigation.sh pcd_file:=PCD/clean_map.pcd config_file:=mid360.yaml visualize:=true enable_chassis:=false
~~~

真车需要硬件负责人确认 CAN 接口、通信速率、急停和速度标定；不要为了消掉报错而删掉检查或擅自改 CAN 参数。

### 提示节点已在运行、重复启动或启动后马上退出

同一台电脑同时只运行一条传感器、建图或导航主流程。回到之前启动程序的终端按 `Ctrl+C`，等节点退出后再切换。若已经没有旧终端，先从日志找最早报错；不要直接用 `killall` 或删除进程文件来清理不认识的节点。
