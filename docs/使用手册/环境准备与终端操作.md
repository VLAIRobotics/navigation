# 环境准备与终端操作

按顺序完成电脑检查、Ubuntu/ROS 2 安装、工作区编译和终端环境准备。MID360 接线、电脑网口和启动参数集中在[设备接入与启动配置](设备接入与启动配置.md)。

<a id="terminal-basics"></a>

## 终端操作入门

本节列出后续命令的执行方式、工作区环境加载方法和多终端操作。

### 1. 命令执行约定

多行命令按顺序执行；行尾的 `\` 是续行符，复制时要保留。Linux 命令区分大小写。

### 2. 打开终端，进入项目目录

按 `Ctrl+Alt+T` 打开终端，在仓库目录运行：

~~~bash
cd /home/nvidia/nav2.0
pwd
~~~

确认 `pwd` 显示仓库路径，再运行：

~~~bash
ls
~~~

列表里应该能找到 `src`、`tool`、`README.md`。如果提示 `No such file or directory`，说明项目不在这个位置：把 `cd` 后面的路径改成你电脑上实际的项目目录，再继续。

### 3. 每个新终端都要加载环境

ROS 2 和本项目的程序包需要先加载到当前终端。每次新开终端，都在项目目录运行下面两行：

~~~bash
cd /home/nvidia/nav2.0
source /opt/ros/humble/setup.bash
source install/setup.bash
~~~

前两条 `source` 命令分别加载 ROS 2 Humble 和本项目编译出来的程序包。

如果第三行报 `No such file or directory`，通常是还没有完成编译。回到[原生安装与编译](环境准备与终端操作.md)，先完成依赖安装和编译，再回来继续。不要在不同终端里只加载其中一部分。

启动脚本会自行加载 ROS 环境，但 `ros2 topic`、`ros2 service` 这类手动检查命令不会；所以每次在新终端手动查数据之前，都要执行上面的三行。

手册里的 `./tool/...` 命令是启动脚本，通常会自行加载环境；直接输入 `ros2 ...` 的检查/保存命令则需要先运行这三行。脚本和 `ros2` 命令都必须在正确的终端里运行。

### 4. 同时用两个终端

运行中的主程序会一直占着它的终端，这是正常的。不要关掉它，也不要在里面继续敲检查命令。

需要一边运行、一边检查或保存数据时：

1. 保留第一个终端，让启动命令继续运行。
2. 再按一次 `Ctrl+Alt+T` 打开第二个终端。
3. 在第二个终端执行“每个新终端都要加载环境”里的三行命令。
4. 在第二个终端运行检查命令或保存地图命令。

例如，第一个终端启动建图，第二个终端调用地图保存服务。后面每个运行流程都会写清楚哪个终端做什么。

### 5. 停止程序

要停止程序，点回正在运行它的终端并按 `Ctrl+C`。切换流程前，等待启动脚本和节点退出；不要直接关电源或拔雷达网线。

如果你在第二个终端运行的是 `ros2 topic hz`（查看话题频率），按 `Ctrl+C` 只会停止频率查看，不会关掉第一个终端里的导航或建图程序。

### 6. 路径和参数

- 以 `/` 开头的是完整路径，例如 `/home/nvidia/nav2.0/PCD/map.pcd`。
- 像 `PCD/map.pcd` 这样的相对路径，是从当前所在目录开始找。先 `cd /home/nvidia/nav2.0`，它才会指向项目里的 `PCD/map.pcd`。
- `config_file:=mid360.yaml` 表示把 `mid360.yaml` 传给名为 `config_file` 的启动参数。冒号和等号都要保留，不要改成空格。
- `true` 表示打开，`false` 表示关闭。第一次只检查数据时，导航命令里要保留 `enable_chassis:=false`，避免启动底盘。
- 命令里出现 `:=`、`--` 或大写字母时，按原样输入。它们不是装饰文字。
- 如果看到 `/path/to/map.pcd`、`你的地图.pcd` 这类示例文字，先换成你自己的实际文件路径，不能把示例占位文字原样输入。

### 7. 遇到报错先做什么

先停在报错的那一步，不要连续复制后面的命令。记下报错前后几行文字，并确认当前目录：

~~~bash
pwd
ls
~~~

若命令提示找不到 ROS 程序包，先在当前终端重新执行 ROS 和工作区的三行加载命令。若提示配置文件、地图文件不存在，检查路径和文件名是否拼对。程序启动后产生的日志在项目的 `logs/` 文件夹。

<a id="computer-check"></a>

## 检查电脑与准备设备

如果这是你第一次装环境，按顺序来。遇到报错先停下来处理，别跳过报错继续执行后面的命令。

### 1. 先判断你用的是哪种电脑

在终端执行：

~~~bash
uname -m
lsb_release -ds
dpkg --print-architecture
~~~

常见结果：

| 电脑类型 | `uname -m` 结果 | 软件包架构 | 应该怎么做 |
| --- | --- | --- | --- |
| 普通台式机/笔记本 | `x86_64` | `amd64` | 可按本文安装 Ubuntu 22.04 桌面版 |
| NVIDIA Jetson | `aarch64` | `arm64` | 保留 JetPack 提供的 Ubuntu；不要使用下方供普通电脑安装的文件 |

ROS 2 Humble 的官方二进制安装平台是 Ubuntu 22.04（Jammy）。Jetson 请先确认系统来自兼容的 JetPack 版本；刷机和升级 JetPack 应按具体 Jetson 型号的 NVIDIA 文档操作。

### 2. 安装方式

- 本项目直接安装到 Ubuntu：ROS 2、Livox SDK 2 和项目依赖都使用本机环境。同一台电脑上的其他代码也可以共用本机工具和文件，无需单独维护容器环境。
- 完整步骤见 [原生安装与编译](#install-build)。已经能运行 `ros2 --help` 并编译过本仓库的电脑，可以跳到 [传感器网络配置](设备接入与启动配置.md#mid360-network)。

### 3. 如果还没有 Ubuntu：下载与安装

#### 普通 64 位电脑

1. 准备一个至少 8 GB 的 U 盘；其中原有文件会在制作安装盘时被清除，先把文件备份到别处。
2. 从 [Ubuntu 官方 22.04 下载页](https://releases.ubuntu.com/22.04/)下载“桌面版 64 位电脑”安装文件。文件名应为 `ubuntu-22.04.5-desktop-amd64.iso`，大小约 4.4 GB。
3. 也可以在另一台 Ubuntu 电脑上用终端下载。以下命令会把安装文件和校验文件保存到“下载”目录：

   ~~~bash
   mkdir -p ~/Downloads
   cd ~/Downloads
   wget https://releases.ubuntu.com/22.04/ubuntu-22.04.5-desktop-amd64.iso
   wget https://releases.ubuntu.com/22.04/SHA256SUMS
   grep 'ubuntu-22.04.5-desktop-amd64.iso' SHA256SUMS | sha256sum -c -
   ~~~

   最后一行显示 `OK` 才表示安装文件下载完整。若显示 `FAILED`，删除损坏的 ISO 后重新下载：`rm ubuntu-22.04.5-desktop-amd64.iso`。
4. 在另一台 Ubuntu 电脑打开“启动盘创建器”，选择刚下载的 ISO 和 U 盘，按界面提示制作启动盘。Windows 电脑可使用 Rufus；选择 ISO 和 U 盘后开始制作。不要在制作过程中拔出 U 盘。
5. 将启动盘插入要安装 Ubuntu 的电脑，重启并按电脑厂商指定的启动菜单键（常见为 F12、F10、Esc 或 Del），选择 U 盘启动。
6. 按安装器提示选择语言、键盘、网络、时区和账户。进入磁盘分区页面后，如果不确定分区含义，停止安装并先备份/咨询管理员。选择“清除整个磁盘”会删除该磁盘上的原系统和文件。
7. 安装结束后重启，拔掉 U 盘，登录 Ubuntu。打开终端，按上面的命令检查系统版本和架构。

> 如果电脑本来已经装好 Ubuntu 22.04，不需要重装系统，直接进入 [原生安装与编译](环境准备与终端操作.md)。

#### NVIDIA Jetson

不要给 Jetson 使用 `ubuntu-22.04.5-desktop-amd64.iso`：它适用于普通 64 位电脑，不适用于 Jetson。Jetson 的系统、显卡驱动和运行环境由 JetPack 配套提供。请先用 [NVIDIA JetPack 官方页面](https://developer.nvidia.com/embedded/jetpack)确认对应型号的安装方式；系统已是 Ubuntu 22.04 时，跳过刷机步骤并继续本手册。

### 4. 需要准备的设备和文件

- 建图需要一台 MID360、以太网线和能连接雷达的网卡；IP 地址应与现场设备配置一致。
- 真机底盘导航需要正确配置 CAN 接口、速度标定和急停。只在桌面查看数据时，按流程显式关闭底盘。
- PCD 地图、录制数据包可能很大。开始录制前检查磁盘空间和输出目录。
- 本手册命令默认在仓库根目录执行，即 `pwd` 所在目录下可以看到 `src/`、`tool/` 和 `README.md`。

## 原生 Ubuntu 安装与编译

下面依次安装 ROS 2 Humble、编译工具、Livox SDK 2，再编译本仓库。命令适用于 Ubuntu 22.04。代码块可以整段复制，等这一块执行完再继续下一块。步骤也可以对照 [ROS 2 Humble 官方 Ubuntu 安装文档](https://docs.ros.org/en/humble/Installation/Ubuntu-Install-Debians.html)。

命令提示输入密码时，输入你的 Ubuntu 登录密码并按回车。输入过程中屏幕不会显示字符，这是正常的。

先认一下这几个名称：ROS 2 是各个机器人程序互相传数据的环境；Humble 是本项目使用的 ROS 版本；`apt` 从 Ubuntu 软件源下载安装软件；`rosdep` 按程序包清单补依赖；`colcon` 编译 ROS 工作区；Livox SDK 2 是 MID360 驱动需要的底层库。

### 第 0 步：打开终端并确认系统

按 `Ctrl+Alt+T` 打开终端，然后执行：

~~~bash
lsb_release -ds
dpkg --print-architecture
~~~

普通电脑应显示 Ubuntu 22.04 和 `amd64`。Jetson 通常显示 `arm64`，并使用 JetPack 配套 Ubuntu。若系统版本不是 22.04，先确认该系统是否有 Humble 二进制包；不要直接照抄下面的发行版命令。

### 第 1 步：准备系统软件源和 UTF-8 语言环境

先更新 Ubuntu 的软件目录，再安装设置软件源和语言所需的工具：

~~~bash
sudo apt update
sudo apt install -y locales software-properties-common curl ca-certificates
~~~

设置 UTF-8 语言环境：

~~~bash
sudo locale-gen en_US en_US.UTF-8
sudo update-locale LC_ALL=en_US.UTF-8 LANG=en_US.UTF-8
export LANG=en_US.UTF-8
locale
~~~

输出中看到 `UTF-8` 即可。ROS 的命令、程序包名称和日志常使用英文；这不影响 Ubuntu 界面使用中文。

`sudo` 表示用管理员权限执行后面的命令；`apt update` 只刷新“有哪些软件可下载”的目录，不会自动安装整套系统更新。终端若问 `Do you want to continue? [Y/n]`，核对正在安装的内容后输入 `Y` 并按回车；密码输入时不显示字符是正常的。

### 第 2 步：添加 ROS 2 软件源并安装 Humble

#### 2.1 打开 Ubuntu Universe 软件源

~~~bash
sudo add-apt-repository universe
~~~

如果系统询问是否继续，按回车。

#### 2.2 下载并安装 ROS 软件源配置

下面的命令会从 ROS 官方发布页取得当前软件源配置包，保存到 `/tmp`，再安装签名密钥和软件源地址：

~~~bash
export ROS_APT_SOURCE_VERSION=$(curl -fsSL https://api.github.com/repos/ros-infrastructure/ros-apt-source/releases/latest | grep -F "tag_name" | awk -F'"' '{print $4}')
echo "$ROS_APT_SOURCE_VERSION"
curl --fail --location -o /tmp/ros2-apt-source.deb "https://github.com/ros-infrastructure/ros-apt-source/releases/download/${ROS_APT_SOURCE_VERSION}/ros2-apt-source_${ROS_APT_SOURCE_VERSION}.$(. /etc/os-release && echo ${UBUNTU_CODENAME:-${VERSION_CODENAME}})_all.deb"
sudo dpkg -i /tmp/ros2-apt-source.deb
~~~

第二行应显示一个版本号。若为空，说明电脑暂时无法访问 GitHub；先检查网络和系统时间，不要继续安装。

这几行的作用依次是：从 ROS 官方发布页取软件源配置包的版本号、把版本号显示出来、按 Ubuntu 版本下载 `.deb` 文件、用系统包管理器安装它。`.deb` 是 Ubuntu 的安装包格式；这一步只配置 ROS 软件源，还没有安装 ROS 本体。

#### 2.3 更新 Ubuntu 软件目录并安装 ROS 2

~~~bash
sudo apt update
sudo apt upgrade
sudo apt install -y ros-humble-desktop
~~~

- `sudo apt upgrade` 会更新当前 Ubuntu 已安装的软件；按屏幕提示确认即可。可能需要一些时间。
- `ros-humble-desktop` 会安装 ROS 2 Humble、RViz 和常用图形程序。本仓库的可视化流程需要桌面版。
- 如果设备没有图形桌面且只打算无图运行，可以将最后一行改为 `sudo apt install -y ros-humble-ros-base`；之后不能在这台机器上运行 RViz。

#### 2.4 检查 ROS 是否安装成功

~~~bash
source /opt/ros/humble/setup.bash
ros2 --help
~~~

如果屏幕出现 ROS 2 命令帮助文字，说明安装成功。如果显示找不到 `/opt/ros/humble/setup.bash` 或 `ros2: command not found`，先处理 ROS 安装报错，不要继续编译。

每个新终端都要加载环境，手动输入 `source /opt/ros/humble/setup.bash` 即可，具体见[终端操作入门](#terminal-basics)。这里不把项目工作区写进终端的全局启动文件，避免这台电脑上其他 ROS 项目误用本仓库的程序包。

### 第 3 步：安装编译工具和 rosdep

~~~bash
sudo apt install -y build-essential cmake gfortran git python3-colcon-common-extensions python3-rosdep ros-dev-tools libpcl-dev
~~~

这些工具分别用于编译 C/C++ 程序、配置 CMake 工程、构建 ROS 工作区、解析程序包依赖。重复安装时，Ubuntu 会提示它们已经是最新版。

第一次使用 `rosdep` 时，初始化依赖索引并下载依赖清单：

~~~bash
sudo rosdep init
rosdep update
~~~

如果 `sudo rosdep init` 提示已经初始化，不必删除已有配置，直接运行 `rosdep update`。

### 第 4 步：下载并安装 Livox SDK 2

本仓库的 MID360 驱动需要 [Livox SDK 2](https://github.com/Livox-SDK/Livox-SDK2)。`rosdep` 不一定会替你安装它，所以需要单独编译。下面使用本仓库原来配置的固定版本，避免每次下载到不同提交：

~~~bash
cd /tmp
curl --fail --location --retry 5 --retry-delay 3 \
  https://github.com/Livox-SDK/Livox-SDK2/archive/08f523c930b2f0ba1e98a6afaa8d7476bf479908.tar.gz \
  --output livox-sdk2.tar.gz
mkdir -p /tmp/Livox-SDK2-src
tar -xzf /tmp/livox-sdk2.tar.gz --strip-components=1 -C /tmp/Livox-SDK2-src
cmake -S /tmp/Livox-SDK2-src -B /tmp/Livox-SDK2-src/build -DCMAKE_BUILD_TYPE=Release
cmake --build /tmp/Livox-SDK2-src/build --parallel 2
sudo cmake --install /tmp/Livox-SDK2-src/build
sudo ldconfig
~~~

这里先把源代码压缩包下载到 `/tmp`，解压后编译，再安装到系统目录。`--parallel 2` 限制同时编译的任务数，减少内存不足的情况。`ldconfig` 更新系统的动态库索引。

确认压缩包下载成功且安装命令没有报错后，可以删除临时源文件以释放空间：

~~~bash
rm -rf /tmp/Livox-SDK2-src /tmp/livox-sdk2.tar.gz
~~~

### 第 5 步：取得本仓库代码

如果仓库已经在电脑上，并且你能在其中看到 `src/`、`tool/`、`README.md`，跳到第 6 步。

如果还没有代码，并且你有这个 GitHub 仓库的访问权限，在终端运行下面的命令下载本仓库。这里用 HTTPS 地址，不需要先配置 SSH 密钥：

~~~bash
cd /home/nvidia
git clone https://github.com/kakou10001/nav2.0.git nav2.0
cd /home/nvidia/nav2.0
~~~

如果 GitHub 提示仓库不存在或没有权限，请先确认账号是否获准访问；私有仓库需要使用组织批准的 Git 登录方式。不要把账号密码或访问令牌写进命令文本。如果代码已经在电脑上，不要再克隆一份；后续命令都应在已有仓库根目录运行。

用下面两条命令确认当前位置：

~~~bash
pwd
ls
~~~

`ls` 输出中应包含 `src`、`tool` 和 `README.md`。

### 第 6 步：安装仓库声明的依赖

先进入仓库根目录（当前示例路径为 `/home/nvidia/nav2.0`），再让 `rosdep` 读取 `src` 内各 ROS 程序包的依赖声明：

~~~bash
cd /home/nvidia/nav2.0
source /opt/ros/humble/setup.bash
rosdep install --from-paths src --ignore-src --rosdistro humble -r -y
~~~

安装过程中如果 Ubuntu 提示需要额外磁盘空间，确认剩余空间足够后按提示继续。若报错，记下第一个报错的程序包名称和整段错误文字；后续重复报错通常是第一个错误引起的。

<a id="build-memory"></a>

### 第 7 步：按用途编译，控制内存占用

**内存有限的开发板不要一次编译整个工作区，也不要使用多个并行 worker。** 工作区包含 FAST-LIO、点云处理和导航相关程序包；全量或并行编译可能耗尽内存并触发系统 OOM。按当前用途逐步构建目标包及其依赖，并把并行 worker 固定为 1。

先构建雷达驱动和 FAST-LIO 所需的包：

~~~bash
cd /home/nvidia/nav2.0
unset AMENT_PREFIX_PATH CMAKE_PREFIX_PATH COLCON_PREFIX_PATH
source /opt/ros/humble/setup.bash
colcon build --packages-up-to fast_lio --parallel-workers 1 --symlink-install
source install/setup.bash
~~~

需要使用 `bringup` 中的建图、地面处理或导航流程时，再构建该目标及其依赖：

~~~bash
colcon build --packages-up-to bringup --parallel-workers 1 --symlink-install
source install/setup.bash
~~~

`--packages-up-to <包名>` 只选择目标包及其依赖，不会主动编译工作区中与该目标无关的包；`--parallel-workers 1` 让 colcon 一次只安排一个程序包。首次编译会较慢。成功时终端末尾应显示 `Summary: ... packages finished`，且失败数量为 0。

如果只改了一个包，且它的依赖已经构建，可用 `--packages-select <包名>` 只重编该包。若单个包仍因内存不足失败，先停止其他占用内存的程序；不要提高并行度或继续启动整工作区编译。更换仓库路径时相应修改 `cd` 命令。不要在编译仍运行时关闭终端或在机器人运行期间覆盖 `install/`。

### 第 8 步：加载工作区并验证

编译成功后，在同一个终端运行：

~~~bash
source install/setup.bash
ros2 pkg list | grep -E 'bringup|fast_lio|livox_ros_driver2|patchworkpp|fastdem'
~~~

如果能看到相关程序包名称，说明工作区已被 ROS 找到。若没有任何结果，确认编译确实成功、当前目录是仓库根目录，并已执行 `source install/setup.bash`。

每个新终端都要单独加载工作区，命令见[终端操作入门](#terminal-basics)。这一步需要手动做，是为了避免其他 ROS 项目打开终端时自动混入本仓库的工作区。

### 修改代码后重新编译

只重新编译被修改包及其依赖，并保持单 worker：

~~~bash
source /opt/ros/humble/setup.bash
colcon build --packages-up-to bringup --parallel-workers 1 --symlink-install
source install/setup.bash
~~~

把 `bringup` 换成实际修改的包名。不要为了修改一个包而重新编译整个工作区。
